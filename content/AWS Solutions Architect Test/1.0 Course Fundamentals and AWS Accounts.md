**AWS Accounts**
AWS Accounts - a container for identities (users) and AWS Resources.

Requires an email address & a credit card. The email address per account must be unique per account.

Each account has its own root user.

The Root User has full control over any AWS Account and any resources created within it & can't be restricted.

The Identity and Access Management (IAM) Service is dedicated to an account.
IAM Users
IAM Groups
IAM Roles

IAM identities managed by the IAM service start off with no permissions. You have to give them permissions.

The management account and the general account are the same thing.
When you create an AWS account, a root user is created. Configure the following on the root account:
- MFA - in addition to username & password.
- A Budget - to protect against unintended costs.
- IAM Identities (a user) called Admin. This is to prevent using the root account.
- A brand new account called production w/ ...
When you create AWS accounts, view them as disposable.

You can use Gmail aliases for multiple accounts.
Example:
catguy@gmail.com
catguy+AWSAccount1@gmail.com
catguy+AWSAccount2@gmail.com
etc...

MFA Factors
- Something you know (password)
- Something you are (biometrics - fingerprint, eye scan)
- Something you have (MFA device)

## IAM Basics
Account root user is created with an account and **can't be restricted in any way**.

Giver least privilege permissions for users, groups, etc.

IAM is a globally resilient service. All data is secure across all AWS regions.

IAM as a service can do as much as the account root user. Your IAM service is fully trusted by your AWS account.

IAM can create 3 identities:
IAM Users - humans or applications that need access to your AWS account.
IAM Groups - Collection of related users.
IAM Roles - Can be used by AWS Services or for granting external access to your account.
	Example: You have EC2 instances & want to give them access to S3. You can create a role which grants access to that service (S3) & then allow the EC2 instances to use that role. You generally use roles when you want to grant services to your account for an uncertain # of entities. Or to give external access to your account.

Policies allow or deny access to AWS services WHEN they're attached to identities (users, groups, & roles). They only have an effect when they're attached to an identity.

IAM has 3 main jobs
- Manages Identities - an ID Provider (IDP)
- Authenticate - (prove who you claim to be - generally w/ username & password)
- Authorize - allow or deny access to resources

We want to create an IAM Admin user which will basically be the same as the root user - so that we can stop using the root user.

## IAM Access Keys
Auth on the command line is done with access keys, not username & password. Access keys are long term credentials (there are more). All long term credentials are used with IAM users.
- An IAM user can have 2 access keys
You can have machine identities that don't use username + password.
An access key is composed of: Access Key ID + Secret Access Key
IAM Users are the only identity that use long term access keys.
IAM Roles don't use access keys.
