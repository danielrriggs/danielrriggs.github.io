## EFS Architecture
Provides network-based file systems which can be mounted within Linux EC2 instances and used by multiple instances at once.

- **EFS** is an implementation of **NFSv4** (a common shared storage standard - Network File System, version 4)
- With EFS, you create **Filesystems** which are **mounted** in Linux (EC2).
	- Linux uses a tree structure for its file system
	- Devices can be mounted into folders in that hierarchy
	- For example, an EFS file system could be mounted into a file system called /efs/media
- EFS Filesystems can be **shared** (mounted) on many EC2 Instances
	- EFS storage exists separately from an EC2 instance
		- EBS is block storage, whereas EFS is file storage, but Linux instances can mount EFS file systems as though they are connected directly to the instance.
- Private service, access to EFS file systems is via **mount targets**, which are things inside a VPC
- EFS file systems can be accessed from **on-premises** via **hybrid networking** methods (even though EFS is a private service)
	- VPC peering, VPN connections or AWS Direct Connect (DX)

![[Elastic File System (EFS).png]]

- EFS runs inside a VPC.
- Inside EFS, you create file systems and these use **POSIX** permissions.
	- // more info on POSIX: [File-system permissions - Wikipedia](https://en.wikipedia.org/wiki/File-system_permissions). Summary: it's a standard for interoperability used in Linux. All linux distros will understand POSIX.
- The EFS file system is made available inside a VPC via **mount targets**. These run from subnets inside the VPC. The mount targets have IP addresses taken from the IP address range of the subnet that they're inside.
	- To ensure HA, put mount targets in multiple AZs.
	- Just like NAT GWs, for a fully HA system, you need to have a mount target in every AZ that a VPC uses.

Things to know for the exam:
- EFS is for **Linux-only** instances
- EFS offers two performance modes - General Purpose & Max I/O
	- **General Purpose** = default for 99.9% of uses
	- **Max I/O** - suitable for anything that's highly parallel - big data, media processing, scientific analysis, etc.
- **Bursting** and **Provisioned** Throughput Modes
	- Burst mode works like GP2 volumes inside EBS - has a burst pool, but the throughput scales with the size of the file systems
- **Standard** and **Infrequent Access** (IA) Classes
	- IA is lower cost. Designed for things which are infrequently accessed.
- Lifecycle Policies can be used with classes (just like S3 // [[4.0 SIMPLE STORAGE SERVICE (S3)#S3 Lifecycle Configuration]]
